## 一、实验与认知教训

### M1 · U6 · 裸查扑空不是 RAG 坏了，先怀疑查询
- **坑**：拿"实验原理"这种 4 字标题裸查，top1 距离 0.3799，比知识导向查询（"基尔霍夫定律和叠加定理的内容是什么"，0.1993）差一大截。
- **教训**：查询设计本身是检索质量的变量。语义检索是"按意思找内容"，不是"按章节名找块"——找写法/找章节这类需求，裸查干不好，正解是查询设计（知识导向）或 metadata 过滤（U9 兑现）。
- **延伸**：诊断顺序"解析→看块全文→切块→检索"是 U6 沉淀的通用排查链。

### M2 · U8 · 切分的收益是纯净度，不是距离数字
- **坑**：设计实验时预期"结构切分后裸查 top1 距离显著低于 0.3596"——实测 0.3682，预期被打脸；且 top3（0.3682/0.3684/0.3712）全是以章节标题开头的块，纯原理**内容**块反而缺席。
- **教训**：①4 字裸查的向量落在"实验X"标题簇里，块首带标题的块占便宜——块构成比距离数字更能说明检索好坏；②结构切分的真实收益=让"纯块"存在（混合块消失），但"纯块必被命中"还差 metadata 过滤一步（U9）；③AI 设计的实验预期也可能错，实测说了算。

### M3 · U6/U7 · distance 是距离不是相似度百分比
- **坑**：容易把 0.2 当"20% 相关"。
- **教训**：cosine 距离 = 1 − 余弦相似度，值域 [0,2]，越小越相关；0.3799≈相似度 0.62，0.1993≈0.80。要百分比自己换算，且换算后也无概率含义。

## 二、工程教训

### E1 · Read 缓冲区 ≠ 磁盘文件（Trae 工具链）
- **坑**：Read 工具返回 IDE 缓冲区实时内容，Edit/Grep/Python 读的是磁盘——用户在 IDE 改了没保存时，两者不一致会导致误判。
- **教训**：验证一律以 Python 读磁盘为准；修改用户打开的文件后必须提示 Revert File。

### E2 · Windows 中文编码必须固定 UTF-8
- **坑**：IDE 默认 GBK 保存，跨工具读写易乱码。
- **教训**：编码假设未验证前禁止执行转换操作；脚本输出前 `sys.stdout.reconfigure(encoding="utf-8")`。

### E3 · 量化诚信：数字必须有实验支撑
- **坑**：拍脑袋写"准确率提升 X%"类指标。
- **教训**：一切写上简历/文档的量化指标必须有对应评测实验支撑；截图数字必须代码重跑复现，禁止引用 OCR 读数。
