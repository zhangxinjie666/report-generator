## 概念讲解

### 1. Embedding：把文本变成"坐标"

**一句话定义**：Embedding（嵌入/向量化）是把一段文本映射成一个**固定长度的数字数组**（向量）的运算，语义相近的文本，得到的向量在空间中**距离更近**。

**例子**："实验步骤" → `[0.021, -0.113, 0.087, ..., 0.044]`（512 个数字）；"操作流程" → `[0.019, -0.108, 0.091, ..., 0.041]`——两个数组几乎处处接近；"猫坐在垫子上"的数组则明显不同。

**为什么需要它**：字符串没法直接算"相似"——"实验步骤"和"操作流程"没有一个字相同，但人知道它们意思接近。**计算机不会读意思，只会算数字**。Embedding 的本质就是给语言造一套"语义坐标系"：把"意思"变成"位置"，让"意思近"变成"距离近"，于是语义问题就变成了几何问题。

**项目中在哪**：`rag_engine.py` 入库时把每个文本块变成向量存进 Chroma；检索时把你的查询语句也变成向量，然后算距离。你在 U6 跑的每一次 `search`，背后都是这个运算。

### 2. 向量长什么样：维度

bge-small-zh-v1.5 输出 **512 维**向量（512 个数字）。这个数字叫**维度**，是模型出厂就定死的。

**维度直觉**：维度越高，能编码的语义细节越丰富——就像用 2 个坐标（经纬度）定位地球够用，但要描述一个人的状态 2 个数字就不够了。同系列模型：bge-small（512 维）→ bge-base（768 维）→ bge-large（1024 维），表达能力递增，但计算和存储成本也递增。

**面试点**："'维度越高越好吗？"——不。高维=高成本（算得慢、存得多），且超出任务需要后收益递减。**工程选型是权衡，不是堆料**：本项目几百个块的小知识库，small 完全够用。

### 3. 余弦相似度：只看夹角，不看长度

**一句话定义**：余弦相似度衡量两个向量**方向的接近程度**，值域 [-1, 1]：1 = 同方向（语义几乎一致），0 = 垂直（无关），-1 = 反方向。

**例子**：两篇都在讲"电路实验操作"的文本，向量方向接近 → 相似度接近 1；一篇讲电路一篇讲菜谱 → 接近 0。**不关心向量长短，只关心朝向**。

**为什么"只看方向"合理**：文本长短会影响向量的"长度"（数值大小），但主题决定"方向"。比较两段话像不像，应该问"朝向一致吗"，而不是"长短一致吗"。

**和 U6 的换算关系（重要）**：Chroma 返回的 **cosine distance = 1 − 余弦相似度**，值域 [0, 2]。所以你 U6 实测的 0.3799 对应相似度约 0.62，0.1993 对应约 0.80——**距离越小 = 相似度越大 = 越相关**。

**项目中在哪**：`rag_engine.py` 里向量做了**归一化**（把长度缩放为 1），归一化之后"点积 = 余弦相似度"，计算又快又稳定。这就是为什么本单元实验要求你统一用归一化向量。

### 4. 模型哪来的：它凭什么懂语义

bge-small-zh 由 BAAI（北京智源人工智能研究院）发布，在大规模中文语料上用**对比学习**训练：让"语义相近的句子对"在训练中互相靠近，"无关对"互相推远——训练完，模型就学会了把语义投射到坐标上。

**你不需要懂训练细节**（那是另一个方向的知识），你需要记住结论：**模型懂语义的范围和上限，由它的训练语料决定**——bge-small-zh 是**中文特化**模型，中文学术/通用文本效果好；拿它去跑英文或专业行话，效果会打折。选 Embedding 模型先问"我的语料是什么语言什么领域"——这和 U6 的"语料决定检索上限"是同一条原则的两面。

### 5. 指令前缀（query prefix）：一个真实的工程细节

bge 系列模型有一个官方建议：**检索场景下，查询语句（query）侧要加一段固定前缀**（"为这个句子生成表示以用于检索相关文章："），而**入库的文档侧不加**。原因：训练时模型就是按这个方式用的——query 带指令、document 是纯文本，两边"格式对齐"检索才准。

**思考题（读完动手实验后做）**：打开 `app/services/rag_engine.py`，搜索 `encode` 的调用处——它给查询加前缀了吗？加了/没加分别会有什么影响？（这是"会读"训练：不需要懂全部代码，只要能定位 encode 调用并对照本节结论。）

## 常见误区

1. **"字面相似 = 语义相似"**。错。这是本单元实验 3 要让你**亲眼目睹**的反直觉现象：共享关键词的两个句子可能方向差很远。"苹果手机"和"吃苹果"共享"苹果"，语义却是两个世界。U6 你的"元问题查询"踩的坑，一半根子在这里。
2. **"Embedding 模型可以随时换"**。错。**不同模型的向量属于不同坐标系**——维度可能都不同，即使维度相同，数值含义也完全不兼容。换模型 = 全量重新入库 + 重建索引。面试常以"换 embedding 模型要注意什么"来考这条。
3. **"相似度绝对值说明质量"**。半错。U6 已实测：同域文档的 distance 全挤在 0.37~0.46。**排序才有意义，绝对值只有跨查询对比时才参考**。
4. **"向量库做了 embedding"**。错。Chroma 只负责**存向量 + 算距离**，"文本 → 向量"这步永远是独立的 Embedding 模型做的。职责分离——这决定了换向量库不用重新 embedding，但换 Embedding 模型必须重新入库。
