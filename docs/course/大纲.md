# 课程大纲（项目线 × 知识线）

> 状态：**已审定（2026-10-24 五个决策点定案；2026-10-25 功能升级与迭代线重排定案，见文末"审定记录"）**，本文件为课程正式目录。
> 结构：第一层 = **项目迭代线**（v1 + v1.x + v2~v12 共 12 条版本线，对应 PRD 迭代清单）；第二层 = 每个迭代下挂的**知识单元**。
> 单元因项目需要而被学，学完立刻用于项目。

## 使用说明

- 单元编号全局唯一（与纪要中 U7~U9 = 向量化/分块/向量库 的引用保持一致）。编号是**知识地图**，不是严格学习顺序——学习顺序按项目需求驱动，大体沿编号走、允许跳跃（当前入口见文末）。
- 2026-10-25 起：新增单元 U46~U49 采用**追加编号**（不重排 U1~U45，保护已完成单元的引用链）；U39（MCP）砍除后编号**空缺不补**。
- 每个单元文档固定结构：学习目标 / 前置知识 / 概念讲解 / 常见误区 / 动手实验（填空式）/ 自测清单 / 单元小结（留白由用户写）。
- 每个单元走四阶段闭环：① 知识输入 → ② 理解（预测题）→ ③ 实操（填空）→ ④ 巩固（费曼小结），缺一不可。
- 实操分工：**知识核心**（RAG 原理、Agent 循环、prompt 设计）用户写、AI review；**工程粘合**（接口接线、文件 IO、配置）AI 写、用户读。
- 标 ★ 的单元是纪要 §5 知识查漏补全项（用户未主动提及、岗位技术链路必需）。
- 状态标记：✅ 已完成 / 🔶 部分完成 / ⬜ 未开始。

## 审定记录（2026-10-24 定案）

1. **单元粒度**：保持 45 个单元（v1 占 14 个），小而完整、闭环快、进度感强。
2. **U28 LangGraph**：纳入，定位为"痛点驱动的重构"——先手写 Agent 循环，以并行生成/失败回环/断点续跑三个真实痛点引入重构；深度视项目实际形态调整，需求撑不起来则降级为认知内容。
3. **护栏时机**：U6/U10 单元含 prompt injection 认知误区提示，U38 深入。
4. **U17 前端速览**：保留，作 Vue3 前的过渡。
5. **学习入口**：U6 开局，U7→U8→U9→U10 闭环后改造搁置的 rag_engine.py；U1/U2 残余随用随补；U3/U4 在项目第 4 步（内容生成）前学。

## 审定记录（2026-10-25 定案：功能升级与迭代线重排）

背景：用户提出"实验全流程"功能方案（专业 RAG / 数据处理与工具调用 / 多模态 / 多轮修改与评审 / 多 Agent 协作 五方向），经逐条评审（技术匹配原则 + 独立意愿测试）定案：

1. **迭代线重排**：12 条版本线——v1.x 语料扩展+评测集、v2 数据处理与工具调用（新增）、v4 对话式修改与评审（新增），原 v2~v11 顺延为 v3~v12；MCP 集成砍除。
